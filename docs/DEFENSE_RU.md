# Подготовка к защите (DSSC5113, Kazakh Profanity Detection)

Цель защиты: показать, что вы понимаете **каждый шаг** от сырого текста до предсказания,
умеете объяснить данные, метрики и ошибки и можете **изменить код** на месте.

---

## 1. Весь проект за 1 минуту

1. **Данные.** KazSAnDRA (175 тыс. казахских отзывов: приложения, маркетплейс, места, книги; CC BY 4.0).
   Меток мата там нет — только звёзды (тональность), поэтому метки я построил сам.
2. **Разметка.** Правила (`labeling_rules.py`) находят кандидатов в мат → неоднозначные (414) проверены
   вручную → **весь тест (1 468) проверен вручную**. Плюс 60 синтетических примеров (только в train).
3. **Очистка и разбиение.** Удаление ссылок/телефонов/e-mail, удаление точных дубликатов,
   почти-дубликаты (косинус ≥ 0,8) — всегда в одном сплите, 70/15/15, seed = 42.
4. **Модель.** TF-IDF по символьным n-граммам (1–4 символа) + логистическая регрессия.
   Словарь n-грамм и IDF обучаются **только на train**.
5. **Выбор настроек** (n-граммы, C) и **порога 0,345** — по валидации.
6. **Тест один раз:** precision = recall = F1 = 0,964 для класса 1; 13 FP, 13 FN из 1 468.

## 2. Как провести один комментарий от текста до ответа

Команда: `python src/explain.py "Шаңсорғыш екі күнде сынды, қотақбас дүкен"`

| шаг | что происходит | где в коде |
|---|---|---|
| 1 | сырой текст | — |
| 2 | `clean_text`: замена ссылок/телефонов на `<url>`/`<phone>`, нижний регистр, `ё→е`, «аааа»→«аа», обрезка до 1000 символов | `src/text_utils.py` |
| 3 | разрезаем каждое слово (с пробелами по краям) на куски по 1–4 символа: `" қот"`, `"қота"`, `"отақ"`, … | `TfidfVectorizer(analyzer="char_wb", ngram_range=(1,4))` в `train.py` |
| 4 | каждому куску из словаря — вес TF-IDF: `(1 + log tf) · idf`; вектор нормируется (длина 1). Неизвестные куски просто игнорируются | там же |
| 5 | логистическая регрессия: `z = w·x + b` (сумма «вес n-граммы × её TF-IDF» + смещение) | `LogisticRegression` |
| 6 | вероятность `p = 1 / (1 + e^(−z))` (сигмоида) | `predict_proba` |
| 7 | если `p ≥ 0,345` → 1 (мат), иначе 0 | `predict.py` |

Для примера выше: `z = +12,333 − 4,789 = +7,544`, `p = 0,999` → **1**. Главный вклад дают куски
`'ота'`, `'қот'`, `'қота'`, `'отақ'`.

## 3. Ключевые понятия (короткие ответы)

* **Почему символьные n-граммы, а не слова?** Одно и то же матерное слово пишется десятками способов
  (*қотақ, котак, kotak, қ\*тақ, қотаққа*). У них общие кусочки (`отак`, `қот`), поэтому модель узнаёт
  и новые написания. Словесная модель увидела бы в каждом варианте «новое неизвестное слово».
* **`char_wb`** — n-граммы берутся только внутри слов (с пробелами по краям), не через границу слов.
* **TF-IDF.** TF — как часто кусок встречается в этом комментарии (у нас `1 + log tf`, чтобы повтор не
  давал слишком много); IDF — насколько кусок редкий во всём train (частые куски вроде «а» весят меньше).
* **Логистическая регрессия.** Линейная модель + сигмоида. Обучение = минимизация **log-loss
  (кросс-энтропии)** с L2-регуляризацией. `class_weight="balanced"` — ошибки на редком классе 1
  штрафуются сильнее (класса 1 всего ~25 %).
* **C** — обратная сила регуляризации: маленькое C = сильнее «сжимаем» веса (проще модель), большое
  C = слабее. На валидации лучшее C = 100 (качество вышло на плато: AP 0,990 → 0,991 → 0,992).
* **Почему порог 0,345, а не 0,5?** Порог выбран на **валидации** как максимизирующий F1 для класса 1.
  На тесте ничего не подбиралось.
* **Почему тест только один раз?** Если подбирать настройки по тесту, тест перестаёт быть честной
  оценкой на новых данных (утечка информации).
* **Почему словарь только на train?** Иначе модель «знает» n-граммы из валидации/теста заранее — утечка.
  В коде это гарантирует `pipeline.fit(train)`: `TfidfVectorizer` внутри пайплайна видит только train.
* **Почему почти-дубликаты в одном сплите?** Если «керемет ойын!!» в train, а «керемет ойын» в тесте,
  модель просто вспоминает ответ, и метрика завышается.

### Метрики (класс 1 = мат)

* **Precision** = TP / (TP + FP) = 346 / (346 + 13) = 0,964 — из всех, кого модель назвала «мат», сколько
  действительно мат.
* **Recall** = TP / (TP + FN) = 346 / (346 + 13) = 0,964 — какую долю всего мата модель нашла.
* **F1** = 2·P·R / (P + R) = 0,964 — среднее гармоническое (низкое, если хоть одна из двух низкая).
* **Матрица ошибок:** строки — правда, столбцы — предсказание: TN = 1096, FP = 13, FN = 13, TP = 346.
* **FP** = чистый отзыв скрыт → цензура честного (часто негативного) мнения покупателя.
  **FN** = мат опубликован → его видят другие покупатели, в т.ч. дети.
  Для автоматического скрытия важнее не делать FP (повысить порог); для очереди модератору важнее
  не пропускать FN (понизить порог).

## 4. Вероятные вопросы и ответы

1. **Откуда метки?** Правила-словарь → ручная проверка неоднозначных → ручная проверка всего теста
   (исправлено 17 из 1 469, т.е. правила ошибались в 1,2 %). Модель правила не видит.
2. **Чем отличается мат от негативного отзыва?** Негатив без матерных слов = 0 (специально добавлено
   много отзывов на 1–2 звезды). Оскорбления без мата (*мал, ақымақ, оңбаған*) = 0.
3. **Смешанный казахский/русский?** Русский мат внутри казахского комментария = 1.
4. **Замаскированные слова?** Если узнаётся матерное слово (*с\*\*а, н\*\*\*, қ\*тақбас*) = 1;
   звёздочки как оформление (`*рахмет*`) = 0. Символ `*` модель сохраняет — это сильный признак.
5. **Синтетика?** 60 примеров, написаны вручную (с помощью ИИ), помечены `is_synthetic=1`, только train.
   Нужны, потому что в реальных отзывах о товарах мата почти нет.
6. **Самая интересная ошибка?** «…қанша уақт **көттім**…» (опечатка «күттім» = «ждал»):
   кусок `көт` — сильный признак мата → p = 0,99. Модель не понимает смысл, только кусочки букв.
7. **Как улучшить?** Больше реальных примеров мата в отзывах о товарах; обработка декоративных `*`;
   больше «трудных» отрицательных примеров (*Амина, Көтенбай, көттім*); дообучить небольшой
   мультиязычный трансформер для учёта контекста.
8. **Длинные комментарии?** Обрезка до 1000 символов (это > 99,99 % отзывов); TF-IDF нормирует длину.
9. **Неизвестные слова?** Нет «словаря слов» — любое слово режется на n-граммы; незнакомые n-граммы
   просто дают 0.
10. **Почему не трансформер?** Мало данных, задача в основном про форму слов, нужно объяснимое решение
    и обучение на CPU за секунды; спецификация разрешает одну модель.

## 5. Как быстро что-то изменить на защите

| просьба | что сделать |
|---|---|
| «Проверьте свой пример» | `python src/predict.py "ваш текст"` |
| «Покажите, почему так» | `python src/explain.py "ваш текст"` |
| «Поменяйте порог на 0,5» | в `models/model_info.json` поставить `"threshold": 0.5`, затем `python src/predict.py ...` / `python src/evaluate.py` (но это уже не честный выбор по валидации — так и сказать) |
| «Попробуйте n-граммы 2–6» | в `config.yaml` → `ngram_ranges: [[1, 4], [2, 5], [2, 6]]`, затем `python src/train.py && python src/evaluate.py` |
| «Без балансировки классов» | в `config.yaml` → `class_weight: null`, переобучить |
| «Другой seed» | `seed: 7` в `config.yaml`, затем `python src/prepare_data.py && python src/train.py && python src/evaluate.py` (сплит изменится; тест-метки, проверенные вручную, останутся только для тех отзывов, что снова попадут в тест) |
| «Исправьте метку» | добавить строку `id,label,note` в `data/labels/manual_labels.csv` и перезапустить `prepare_data.py` → `train.py` → `evaluate.py` |

После любых изменений — `git checkout -- config.yaml models results` чтобы вернуть сохранённую версию.
